v1 → v2, in one line

A working prototype hit a ceiling: fixed grid, preprocessing-only toolbar, per-op routes, clipped text. v2 keeps the good substrate (canvas, ledger, theme) and rebuilds the shell around MNE's object graph.

The one bet

One registry entry per MNE operation, one card per MNE plot, one renderer, one provenance graph. Every new capability is data, not code. See BUILD_PLAN_V2.md.

What every screen earns
  1. 1Container-centricThe left rail is MNE's object graph: Raw → Epochs → Evoked → Spectrum/TFR → Source. Pick an object, the workspace reshapes to it.
  2. 2Dense but not clutteredEvery label owns its box. Tabular numerals, real breakpoints, one type scale. Density from information, not from cramming.
  3. 3Modular canvasViews are cards you add / swap / arrange. A workspace preset is just a saved layout. Nothing is hard-wired into the shell.

Notes & decisions

v1: auto-loads a synthetic 32-ch demo, upload is a secondary link, 7 formats. This proposes: a real entry point for every MNE input.

  1. Format + modality grid. PROPOSED — reader registry (P0.10) covers ~25 formats; the Info decides which modality stages appear later. MEG/fNIRS/iEEG are real MNE inputs, not EEG-only.
  2. Sample datasets. PROPOSED — mne.datasets.* one-click fetch (tracked job). Replaces the single hand-rolled synthetic demo; keep that as an offline fallback.
  3. Recent + bundle. PROPOSED — sessions persist to ~/.eegvis/sessions/ (ledger + container snapshots), so refresh / reopen doesn't lose work. v1 loses everything on reload.
  4. Multi-file drop. OPEN Q — group-by-stem on a folder drop vs an explicit "add sidecar" step for BrainVision/EEGLAB.
  5. Plugin path. PROPOSED — eegvis.launch(raw) posts an in-memory Raw; every dev iteration and the real use-case go through the same door.
Prior art
MNE's own raw.plot() is a matplotlib window per object. EEGLAB / Brainstorm are desktop GUIs tied to their own file stores. The bet: a browser session you can hand a URL to, seeded from any MNE reader.

Notes & decisions

v1: a fixed 5-panel grid, a preprocessing-only dropdown toolbar, a 9-item F-key strip, an 8-stat ticker that clips below ~950px. This proposes one coherent shell driven by registries.

  1. Command bar. PROPOSED — visible ＋ Operation button and ⌘K, both dispatch the operation registry (P0.2). Only ops whose input type matches the active container show. Capability pills replace the cramped ticker.
  2. Container rail. PROPOSED — the lineage DAG (P0.1). Click a node = active container; the canvas + offered ops reshape. Ghost = not created yet, click to see how. This is the whole nav model.
  3. Inspector. PROPOSED — one context panel (channel / component / label / step / edge) replacing v1's scattered in-panel detail panes.
  4. Transport. OPEN Q — real play/scrub/speed/loop driving the shared cursor. v1 has a Space-bar rAF sweep that pauses in background tabs and doesn't animate the spectral panels. Windowed PSD (P5) makes them move.
  5. Provenance strip. PROPOSED — the DAG as a filmstrip (P0.6); click a node to time-travel, branch to compare. Export menu lives here.
Prior art
Bloomberg / Persyst terminals: dense, keyboard-first, but fixed layouts. Observable / Jupyter: modular but no domain model. The bet: a domain-shaped shell (MNE's graph) with a modular canvas inside it.

Notes & decisions

v1: preprocessing is 6 fixed toolbar dropdowns; everything else (ICA, epochs, export) is elsewhere or absent. A ⌘K palette was built then deleted. This proposes one surface generated from the registry.

  1. Ops filtered by input type. PROPOSED — the registry (P0.2) knows each op's input container. Active = Raw → you see Raw ops, grouped by MNE stage. Select Epochs → the list becomes reject / metadata / average.
  2. Auto-generated form. PROPOSED — <ParamForm> renders from the op's Pydantic → JSON schema (P0.8/P0.9). ~60 ops, zero bespoke form code. x-widget hints for channel-picker / band-picker.
  3. Preview where cheap. OPEN Q — filter response, ICA overlay, epoch count: which ops get a live preview vs apply-then-inspect. Default: preview if it's a pure function of params.
  4. Apply → ledger + optional branch. PROPOSED — every op appends a DAG node and its pipeline.py line. "Apply to a branch" forks (P0.6) to compare alternatives without losing the current line.
  5. Long ops. PROPOSED — ICA / forward / TFR / stats return a job_id; the form closes, a progress chip appears in the transport (P0.3).
Prior art
Blender / Nuke node menus; VS Code command palette. The bet: the palette is the API surface — anything MNE can do to the active object is one fuzzy search away, and it writes the script.

v1: the "Scalp field" panel is an inverse-distance interpolation of sensor voltages drawn as an oblique wireframe — not a brain, and there's no inverse pipeline behind it. This proposes the real thing, honestly gated.

  1. Setup wizard. PROPOSED — 5 gated steps (P0.7): fetch_fsaverage (~1 GB job) → BEM + make_forward_solution → coregistration → compute_covariance → make_inverse_operator. Each cached; each a ledger node.

  1. Every label owns its box. PROPOSED — truncate + tooltip, never clip. Tabular numerals for all numeric data. One type scale, one spacing rhythm. This is P0.9 and it's non-negotiable.
  2. Primitives as code. PROPOSED — Card / Inspector / ParamForm / DataTable / Toolbar / Chip. "Cluttered and ugly" is a structural fix, done once, not per-panel polish.
  3. Real breakpoints. PROPOSED — 3 layouts by container width; the inspector and rail degrade gracefully; <768 is review-only (no overflow:hidden trap). v1 has none.
  4. Keep from v1. NOW — the sync-paint canvas substrate, themeTick repaint, Tailwind v4 tokens, the "dim don't blank on stale" rule. Those are good.
  5. Aesthetic. OPEN Q — "cool but clean": a restrained instrument look (thin rules, monospace data, one accent, generous negative space) vs more expressive. Wireframe stays neutral; pick in hi-fi.
Prior art
Linear, Vercel dashboards, Ableton — dense, calm, one accent. Not Bloomberg's wall of orange. Information density from hierarchy and whitespace, not from filling every pixel.
